## 2. Foursquare のエクスポートの形式が変わったとき

エクスポートの形式は公式に文書化されておらず、予告なく変わりうる(リスク R-2)。

**気づき方**

- 取り込みの分析結果に「このアプリが知らない項目がありました(…)」と出る。項目名だけが警告に出る(値は出ない)。
- 取り込みが「エクスポートの形式が想定と違います」(`E-IMPORT-FORMAT`)で止まる。
- 利用者からの報告(画面に表示されたエラーの種類つき)。

**直す場所**

| 変更 | 場所 |
|---|---|
| チェックインの項目が増えた・名前が変わった | [records.ts](../../src/lib/export/records.ts) の `checkinSchema`(検証)と、`KNOWN_CHECKIN_KEYS`(既知の項目。ここに無い項目名が警告になる) |
| 検索・表示に使う項目を増やす | [model.ts](../../src/lib/model.ts) の `RawCheckin`・`CheckinRecord`、[records.ts](../../src/lib/export/records.ts) の `validateCheckin`・`deriveRecords`・`buildSearchText`。**保存形式の版を上げ、移行で raw から作り直す**(3.)。作り直せない項目なら、再取り込みを案内する |
| 写真の URL の形が変わった | [records.ts](../../src/lib/export/records.ts) の `PHOTO_PREFIX_RE`・`PHOTO_SUFFIX_RE`・`RELATED_HOSTS`。表示側は [urls.ts](../../src/lib/urls.ts)。CSP の `img-src`(`https://*.4sqi.net`)も確認する |
| ファイル名・分割の仕方が変わった | [files.ts](../../src/lib/export/files.ts) の `EXPORT_FILE_RE` |
| ZIP の形式が変わった | [zipReader.ts](../../src/lib/zip/zipReader.ts)(今は stored・deflate・ZIP64 に対応) |
| 上限が足りなくなった | [constants.ts](../../src/lib/constants.ts) の `LIMITS`(端末の性能と相談して上げる) |

**あわせてやること**

- `tests/fixtures/export-2026/` と、[fake-export.mjs](../../scripts/lib/fake-export.mjs) を新しい形に合わせる。実物は入れない。値はすべて架空にする。
- [実装メモ](../3_detailed%20design/00_%E5%AE%9F%E8%A3%85%E3%83%A1%E3%83%A2.md)の1章(実物で確認したこと)を更新する。
- 古い形式の ZIP も読めることを、単体テストで確かめる(`createdAt` が UNIX 秒の旧形式などは、すでにテストがある)。

**手順の文言**

- [ImportGuide.tsx](../../src/features/import/ImportGuide.tsx) の画面名・ボタン名・URL(`FSQ_PRIVACY_SETTINGS_URL`)。2026-10-22 時点は、ブログ記事と公式寄りの情報を元に書いたもので、最新の画面を見て確かめたものではない。実際に申し込んで確認し、ずれがあれば直す。

## 3. 保存形式(IndexedDB)を変えるとき

利用者のデータはブラウザの中にしかない。移行を誤ると、利用者のデータを壊すか、再取り込みを強いることになる。

1. [schema.ts](../../src/lib/db/schema.ts) の `DB_VERSION` を上げる。
2. [migrations.ts](../../src/lib/db/migrations.ts) の `MIGRATIONS` に、新しい版への移行を足す。
   - 抽出項目や `normalizeForSearch`(検索用の正規化)を変えたときは、`rebuildDerivedValues` で raw から作り直す。
   - raw から作り直せないときは、データを消して再取り込みを案内する。
3. 移行の単体テストを足す([db.test.ts](../../tests/unit/db.test.ts))。
4. 古い版で開いている他のタブが、接続を閉じて案内を出すことを E2E で確かめる。

**特に注意**: [text.ts](../../src/lib/text.ts) の `normalizeForSearch` を変えると、保存済みの検索用テキストと食い違い、検索が合わなくなる。必ず版を上げる。

## 4. 更新後の確認(依存・Next.js・設定の変更のあと)

```bash
npm ci
npm run typecheck && npm run lint && npm test
npm run build            # 開発サーバー(next dev)は止めておく
npm run test:e2e
```

- E2E は、CSP の違反・外部への通信・コンソールのエラーが無いことも確かめる。ここで落ちたら、ヘッダーか依存の変更が原因のことが多い。
- `next dev` を動かしたまま `npm run build` や E2E を実行すると、`.next` の競合で止まることがある。

**Next.js を更新したときに特に見る点**

| 点 | 理由 |
|---|---|
| `out/` の中に `__next.xxx.__PAGE__.txt` が出ているか | Windows でのビルドでは、区切りがフォルダになる不具合があり、[fix-export-segments.mjs](../../scripts/fix-export-segments.mjs) で直している。修正されたら、このスクリプトは不要になる(Vercel の Linux では何もしない) |
| 各 HTML の先頭に CSP の meta が入っているか | [inject-csp.mjs](../../scripts/inject-csp.mjs) は、HTML の `<meta charSet="utf-8"/>` の直後に入れる前提で書いている。Next.js の出力が変わると入らなくなる |
| インラインスクリプトのハッシュ | Next.js がインラインスクリプトの出し方を変えると、CSP でブロックされる。E2E の CSP チェックで分かる |
| ワーカーの読み込み方 | Turbopack がワーカーを同じオリジンのチャンクとして出力することを前提にしている(実装メモ 2.7) |

## 5. 規約・表示の文言

| 項目 | 場所 | 見るタイミング |
|---|---|---|
| 非公式である旨・商標の免責文 | [legal.ts](../../src/lib/legal.ts) の `UNOFFICIAL_NOTICE`・`TRADEMARK_NOTICE`(フッターと「このアプリについて」に出る) | 商標ガイドラインが変わったとき |
| アプリ名・ドメイン | [constants.ts](../../src/lib/constants.ts) の `APP_NAME`、`manifest.webmanifest`、アイコン | 公開前(D-8)。**公開後にドメインを変えると、利用者の保存データは引き継げない** |
| 外部へのリンクの URL | [legal.ts](../../src/lib/legal.ts) の `REPO_URL`・`ISSUES_URL`・`BLOG_URL` | ブログの解説記事を公開したら、`BLOG_URL` を記事の URL に変える。「このアプリについて」の「公開する予定です」も「公開しています」に直す |
| プライバシーポリシー | [privacy/page.tsx](../../src/app/privacy/page.tsx)(制定日を含む) | 外部リンク・外部への通信・保存するデータを変えたとき。制定日(または改定日)も直す |
| 「できること・できないこと」 | トップ・「このアプリについて」・検索のヒント | 検索対象を変えたとき(例: カテゴリの補完を入れたとき) |

**規約に関わる変更のとき**

- 広告・アフィリエイト・解析ツール・外部のスクリプトを入れる場合は、設計の前提(基本設計 P-1・P-7、要件 N-11・N-13)と、プライバシーポリシーの「使いません」の記載、Foursquare の「個人的・非商用」の利用許諾との関係を見直す。商用化する場合は、事前に法務確認(弁護士か Foursquare)を行う。
- 外部の AI にデータを送る機能は、「データは端末の外に出ない」という約束を変えるため、設計書の改訂とプライバシーポリシーの変更が先に必要。

## 7. 利用者からの報告への対応

運営者にはデータもエラーも届かない(基本設計 9.8)。手がかりは、利用者が書く Issue に添えられる「エラーの種類」だけである。

| コード | 意味 | 見る場所 |
|---|---|---|
| `E-IMPORT-{種別}` | 取り込みの失敗。種別は [errors.ts](../../src/lib/import/errors.ts) | 文言は [messages.ts](../../src/features/import/messages.ts) |
| `E-APP-UNSUPPORTED`・`E-APP-STORAGE`・`E-APP-UNEXPECTED` | 非対応のブラウザ・保存領域が使えない・予期しないエラー | [StorageGate.tsx](../../src/features/app/StorageGate.tsx)・[error.tsx](../../src/app/error.tsx) |
| `E-SEARCH-PREPARE`・`E-SEARCH-QUERY` | 検索の準備・検索の失敗 | [SearchView.tsx](../../src/features/search/SearchView.tsx) |
| `E-DATA-DELETE` | データの削除の失敗 | [DataView.tsx](../../src/features/data/DataView.tsx) |

- Issue には、チェックインの内容(店名・コメント・位置・写真)を書かないよう、アプリ内で案内している。書かれていた場合は、編集か削除をお願いする。
- 再現に実データが必要な場合は、`npm run fixture` で架空データを作って試す。実データはこのリポジトリに入れない。
