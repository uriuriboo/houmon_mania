## 1. 実物のエクスポートで確認したこと(S-1)

2026-10 に取得した実物(チェックイン 1,910 件、写真の情報 299 件)で確認した。実物はリポジトリに入れず、形だけを写した架空の fixture を `tests/fixtures/export-2026/` に置いた。

| 確認項目 | 結果 | 設計への影響 |
|---|---|---|
| ファイル名と分割 | `checkins1.json`・`checkins2.json`(1000件ずつ)、`photos1.json`。他に `users.json`(本人・友人)、`comments.json`(他人のコメント)、`shares.json`、`uniqueDevices.json`、`venueRatings.json`、`paymentProfiles.json`、各 `.csv`、`readme.html`、`pix/`(写真の実ファイル) | 想定どおり。読むのは `checkins*.json` と `photos*.json` だけ |

| createdAt | `"YYYY-MM-DD HH:MM:SS.ffffff"`(UTC) | 想定どおり |
| visibility | `closeFriends` が大半。**項目が無いレコードがある**(50件) | 無い場合は「記録なし」と表示 |
| 座標 | **トップレベルに `lat`・`lng` がある**(全件)。`location` は無い | raw に保存する(17章 D-7 の市区町村の補完に使える) |

## 2. 基本設計からの変更・追加

| No | 項目 | 基本設計 | 実装 | 理由 |
|---|---|---|---|---|
| 2.1 | 検索対象 | 店名・コメント・場所名・イベント名 | 店名に `venue.canonicalName`(現地語の店名)を加えた。一覧と詳細は `canonicalName` を主に、英字表記の `name` を補助に表示する | S-1。`canonicalName` を検索しないと、日本語の店名で約半数が見つからない |
| 2.2 | ホスティング | Netlify(`netlify.toml` と、ビルド後に生成する `out/_headers`) | **Vercel**(`vercel.json`)。画面の CSP はビルド後に各 HTML へ `<meta http-equiv="Content-Security-Policy">` として埋め込む。meta では効かない `frame-ancestors` と、ワーカーのスクリプトの CSP は `vercel.json` のヘッダで付ける | 2026-10-22 ユーザー判断(17章 D-11)。`vercel.json` はビルドの前に読まれるため、ビルドで変わるハッシュをヘッダに入れられない |
| 2.3 | UI 部品 | shadcn/ui(Base UI)と toast | ネイティブの要素(`<dialog>`・`<select>` など)と Tailwind の小さな部品(`src/components/ui/`) | 依存の最小化(10.1)。必要な部品が少なく、Base UI が付けるインラインのスタイル属性も避けられる |
| 2.4 | ZIP の展開 | ライブラリ(詳細設計で比較) | 自前の小さな実装(`src/lib/zip/zipReader.ts`)。目次の部分読み込み、ZIP64、`DecompressionStream` での展開と実際の展開量での停止、CRC の検証 | 9.2.2 の条件をすべて満たし、依存を増やさない |
| 2.5 | IndexedDB のラッパー | 詳細設計で比較 | `idb`(8.0.4) | 薄く、広く使われている |
| 2.6 | 保存形式の移行 | 取り込みワーカーが排他ロックを取って行う | IndexedDB の versionchange トランザクションの中で行う(`src/lib/db/migrations.ts`) | versionchange トランザクションは仕様上、他のすべての接続が閉じるまで始まらない排他的なもので、取り込み・削除と同時に走らない。raw から値を作り直す関数(`rebuildDerivedValues`)を用意した |
| 2.7 | ワーカーの形式 | — | Turbopack がワーカーを、同じオリジンのチャンクを `importScripts` で読む形にバンドルする。ワーカーの CSP は `script-src 'self'` で動く | ビルドの出力で確認 |
| 2.8 | Windows でのビルド | — | Next.js 16.4 を Windows でビルドすると、先読み用のファイル(`__next.search.__PAGE__.txt`)がフォルダとして出力される。`scripts/fix-export-segments.mjs` で直す(Linux では何もしない) | ローカルの確認を本番と一致させるため |
| 2.9 | Trusted Types | S-4 で確認して決める | 入れていない | Turbopack の実行時がスクリプトの URL を設定するため、既定のポリシーなしでは動かない見込み。必要なら別途検証する |
| 2.10 | 文中のリンク | — | 常に下線を付ける(`globals.css`) | axe の検査で、色だけで区別されていると指摘された(WCAG 1.4.1) |
| 2.11 | CI・依存の更新 | 自動更新の提案(Renovate または Dependabot)| GitHub Actions(`.github/workflows/ci.yml`。PR のときだけ動く)と Dependabot(`.github/dependabot.yml`。週1回、公開から数日待つ) | 2026-10-22 ユーザー判断 |
| 2.12 | 外部へのリンク | — | ヘッダーに GitHub とブログ、「このアプリについて」にツールの解説記事(ブログ)・リポジトリ・Issues、取り込み画面に Foursquare のプライバシー設定のページ | 通常のリンクだけで、外部のスクリプト・画像は読み込まない。プライバシーポリシーの 10章に記載 |
| 2.13 | アクセス解析 | 第三者のスクリプトを読み込まない(P-7) | **入れた(2026-10-23)**。`@vercel/analytics` を [web-analytics.tsx](../../src/components/web-analytics.tsx) に包み、トップ・このアプリについて・プライバシーポリシーの3ページだけに置く(layout には置かない)。自動の計測は止め、そのページの表示だけをパスで送る。mode は production に固定する(既定だと開発時に外部の va.vercel-scripts.com を読む)。検索・取り込み・データ管理は読み込みも送信もしない(e2e の analytics.spec.ts で確認)。GA4 は必要になったら | 2026-10-22 ユーザー判断。プライバシーポリシーと画面の文言は直した |

## 4. 表示するエラーの種類

| コード | 場面 |
|---|---|
| `E-IMPORT-{種別}` | 取り込み。種別は `src/lib/import/errors.ts`(`NO_EXPORT_FILES`、`MULTIPLE_EXPORTS`、`FORMAT`、`TOO_LARGE`、`QUOTA`、`BUSY` など)。文言は `src/features/import/messages.ts` |
| `E-APP-UNSUPPORTED` / `E-APP-STORAGE` / `E-APP-UNEXPECTED` | 対応していないブラウザ / 保存領域が使えない / 予期しないエラー |
| `E-SEARCH-PREPARE` / `E-SEARCH-QUERY` | 検索の準備 / 検索の失敗 |
| `E-DATA-DELETE` | データの削除の失敗 |
