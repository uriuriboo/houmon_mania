# 10. セキュリティ設計

> [基本設計書 目次](README.md) ｜ 前: [9. 方式設計](09_方式設計.md) ｜ 次: [11. 非機能設計](11_非機能設計.md)

---

サーバーにデータもアカウントも無いため、サーバー側の攻撃(不正ログイン、他人のデータの閲覧、SQL インジェクション、総当たり)は成立しない。守る対象は**利用者の端末の中にある位置履歴**で、主な脅威は「混入したスクリプトによる持ち出し」と「同じ端末を使う他人による閲覧」である。

持ち出しへの対策は、**スクリプトを混入させないこと**を主とする(P-7)。CSP は、混入したスクリプトの通信先を絞って持ち出しを難しくする補助の対策である。画面の遷移(`location` の書き換え)・新しいウィンドウ・WebRTC・DNS の先読みなど、CSP では止められない経路が残るため、CSP だけで持ち出しを防げるとは考えない。

## 10.1 脅威と対策

| 脅威 | 対策 | 要件 |
|---|---|---|
| XSS(読み込んだデータに仕込まれたスクリプト) | React の自動エスケープ。店名・コメント(shout)などはテキストとして表示し、HTML として挿入しない(`dangerouslySetInnerHTML` を使わない)。リンク・画像の URL は検証した値から組み立てる(9.4)。Trusted Types(`require-trusted-types-for 'script'`)で、HTML の文字列を DOM に挿入する処理を禁止できるか S-4 で確認する | P-6 |
| 表示の偽装 | 双方向制御文字(U+202E など)や制御文字で文字の並びを偽装した店名・コメントは、表示の前に制御文字を取り除く(5.5) | P-6 |
| スクリプトによるデータの持ち出し | 第三者のスクリプト(解析・広告・外部 CDN)を一切読み込まない。CSP で、画面とワーカーの通信先を自サイトに、画像の取得先を自サイトと Foursquare の画像 CDN に限る(10.2)。DNS の先読みを止める(`X-DNS-Prefetch-Control: off`) | N-13 |
| 依存パッケージの改ざん(サプライチェーン) | 依存は必要最小限にし、ロックファイルで版を固定する。更新は自動更新の提案(Renovate または Dependabot)を確認してから取り込む。`npm audit` を定期的に行う。CSP により、改ざんされたコードがあっても外部への送信を難しくする | N-13 |
| 配信経路の乗っ取り | GitHub と Netlify のアカウントは2段階認証を必須にする。main ブランチは保護し、直接の push を禁止する。Netlify の Snippet injection(配信する HTML へのスクリプトの差し込み)は使わない。デプロイの通知を受け取り、身に覚えのないデプロイに気付けるようにする | N-13 |
| 同じ端末・ブラウザを使う他人による閲覧 | 取り込み画面とトップで、共有の端末では使わないよう案内する。データ管理画面から即時に削除できる。削除では閲覧履歴と画像のキャッシュが消えないことも案内する(9.5)。検索ボックスの自動補完を無効にする | N-01 |
| 悪意のあるファイル(圧縮爆弾、巨大な JSON、深い入れ子) | 必要なファイルだけを展開し、実際に展開したバイト数で上限を判定する。目次のファイル数・展開後の大きさ・件数に上限を設ける(9.2.2)。処理はワーカーで行い、画面を固めない | N-12 |
| 不正な値(型・範囲・長さの不正、`__proto__` などのキー) | zod で検証し、許可した項目だけで raw を組み立て直す(読み込んだオブジェクトをそのままコピーしない)。不正なレコードは保存しない | P-6 |
| 検索式の悪用 | 長さ・語数・深さの上限。検索式は構造に変換して照合し、文字列からコードを作って実行しない(`eval`・`new Function` を使わない。zod も `jitless` で使う) | N-10 |
| クリックジャッキング | CSP の `frame-ancestors 'none'` | — |
| 通信の盗聴・改ざん | HTTPS のみ(HSTS) | — |
| 検索語・閲覧内容の漏えい | 画面の状態は URL の `#` 以降に持ち、サーバーに送らない(P-1)。リファラを送らない。ブラウザの閲覧履歴とその同期には残る(9.5、17章 D-10) | N-11 |

## 10.2 セキュリティヘッダ【暫定 S-4】

値の詳細は詳細設計で定める。

**付け方**: Next.js の静的書き出しでは設定ファイルのヘッダ指定が使えないため、Netlify の仕組みで付ける。

| ヘッダ | 置き場所 | 理由 |
|---|---|---|
| CSP | ビルドの後に生成する `out/_headers` | インラインスクリプトのハッシュがビルドごとに変わるため、ビルドの後に計算して書き出す |
| CSP 以外(内容が変わらないもの) | `netlify.toml` | — |

CSP は `out/_headers` だけに書き、`netlify.toml` には書かない(両方に書くと同じパスに複数の CSP が付くおそれがあり、その場合はすべてを満たすものだけが許可されて意図しない動作になるため)。

**画面(HTML)に付けるヘッダ**:

| ヘッダ | 方針 |
|---|---|
| Content-Security-Policy | `default-src 'self'`、`script-src 'self'` とインラインスクリプトのハッシュ、`connect-src 'self'`、`img-src 'self' data: blob: https://*.4sqi.net`、`worker-src 'self'`、`style-src 'self'`(必要なら `'unsafe-inline'`)、`object-src 'none'`、`base-uri 'none'`、`form-action 'none'`、`frame-ancestors 'none'`、`manifest-src 'self'`。Trusted Types の `require-trusted-types-for 'script'` は S-4 で動作を確認して決める |
| Referrer-Policy | `no-referrer` |
| X-Content-Type-Options | `nosniff` |
| X-DNS-Prefetch-Control | `off` |
| Permissions-Policy | 使わない機能(カメラ、マイク、位置情報など)を無効にする。画面のスリープ防止(`screen-wake-lock`)は取り込みで使うため無効にしない(9.2.1) |
| Strict-Transport-Security | 有効(Netlify の HTTPS 設定) |
| Cache-Control | HTML は短め、ハッシュ付きの JS・CSS は長期 |

**ワーカーのスクリプトに付けるヘッダ**: 専用ワーカー(Dedicated Worker)は、画面の CSP を引き継がず、ワーカーのスクリプトの応答に付いた CSP に従う。そのため、ワーカーのスクリプトを含む `/_next/static/*` にも CSP を付ける: `default-src 'none'`、`script-src 'self'`、`connect-src 'self'`。これが無いと、混入したスクリプトがワーカーの中から外部へ送信できてしまう。S-4 で、ワーカーの中からの外部への `fetch` が拒否されることを確認する。

**インラインスクリプトのハッシュ**: Next.js の静的書き出しは、ページの HTML にインラインスクリプトを含める。ビルドの後に各 HTML のインラインスクリプトのハッシュを計算して CSP に入れる処理を用意する。それが難しい場合は `script-src 'self' 'unsafe-inline'` とし、`connect-src` と `img-src` を厳しく絞ることでデータの持ち出しを難しくする(S-4 で確認)。

## 10.3 秘密情報

本アプリは秘密情報(API キー・パスワード・署名鍵)を持たない。環境変数にも秘密は置かない。
