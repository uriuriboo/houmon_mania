# 0. 本書の位置づけ

> [基本設計書 目次](README.md) ｜ 前: — ｜ 次: [1. 前提条件・決定済み事項](01_前提条件.md)

---

本書は、要件定義書(v2.0)を受けて、システムを「どう実現するか」の方式を定める。

| 区分 | 内容 |
|---|---|
| 本書の範囲 | システム構成、機能構成、画面構成・画面遷移・UI方針、ブラウザ内の保存データの設計、インタフェース概要、主要処理方式(取り込み・検索・保存領域・削除)、セキュリティ、非機能、開発・運用環境、技術スタックの確定 |
| 範囲外(詳細設計書で扱う) | 保存形式の最終値(ストア・インデックス・項目の型と上限値)、ワーカーとのメッセージの項目定義、画面項目定義・コンポーネント設計、メッセージ/エラーコード一覧、例外分岐を含む詳細シーケンス、テスト設計 |

## 0.1 方式変更の経緯

| 版 | 方式 | 変更の理由 |
|---|---|---|
| 0.9 | Foursquare API でチェックインを同期し、サーバーに保存する | — |
| 1.0 | 利用者が公式エクスポートをアップロードし、サーバー(Supabase)に保存する。ログインは Google とメール | Foursquare の API 利用ガイドラインが、一般の開発者にデータのサーバー保存を禁じていたため |
| **2.0(本書)** | **利用者が公式エクスポートをブラウザで読み込み、データはブラウザの中だけに保存して、検索もブラウザで行う。ログインなし** | 自分のデータを自分で検索する用途なら、データを預かる必要もログインも無いため(2026-10-16 ユーザー判断) |

旧版は `doc/archive/` に保管している。

この方式では、次の2点を受け入れている。

- エクスポートに住所・カテゴリが含まれないため、**検索対象は店名とコメント(shout)が中心になる**(F-22 の変更)。
- 新しいチェックインを反映するには、利用者がエクスポートを再申請して読み込み直す必要がある。データは端末(ブラウザ)ごとに別になる。

## 0.2 決定事項の表記

| 表記 | 意味 |
|---|---|
| 【決定】 | 本書で確定する |
| 【暫定 S-n】 | 実地検証 S-n(報告書 16.3)の後に確定する |

## 0.3 用語

| 用語 | 意味 |
|---|---|
| エクスポート | Foursquare 公式のデータダウンロード(Swarm / Foursquare の設定 → Privacy Settings → "Initiate Data Download Request")で届く ZIP ファイル |
| チェックインレコード | エクスポートの `checkins*.json` に入っている、チェックイン1件分の JSON |
| 取り込み | エクスポートを読み込み、チェックインをブラウザ内の保存領域に保存する一連の処理 |
| 保存領域 | ブラウザが Web サイトごとに用意する保存場所。本アプリは IndexedDB を使う。サイト(オリジン)ごと・ブラウザごとに別で、他のサイトからは読めない |
| 永続化 | ブラウザに「容量が足りなくなっても、このサイトのデータを自動で消さない」よう求めること(`navigator.storage.persist()`) |
| ワーカー | 画面の処理とは別に動くブラウザ内の処理(Web Worker)。ZIP の展開や検索など重い処理を行い、画面が固まらないようにする |
| venue | チェックイン先のスポット(店・施設)。エクスポートには ID・名前・Foursquare 上の URL だけが入っている |
| shout | チェックイン時に本人が書いたコメント。本書では「コメント(shout)」と書く |
| raw | チェックインレコードから、保存してよい項目だけを取り出して組み立て直した JSON(9.2.3) |
| 中間AST | 検索式を解析した結果を、AND / OR / 語 だけで表した木構造 |
