# 3. 技術調査の結果と方式決定

---

詳細と根拠は技術調査報告書を参照。

| 項目 | 結論 | 方式 | 状態 |
|---|---|---|---|
| 規約 | API で得たデータはサーバー保存禁止。エクスポートは利用者本人のデータで、本アプリはそれを預からない | エクスポートをブラウザ内で扱う方式(0.1) | 商用化時は法務確認 |
| エクスポートの形式 | `checkins*.json`(1000件ずつ)と `photos*.json` などを含む ZIP。チェックインの venue は ID・名前・URL のみ。座標の有無は情報が矛盾 | 7.1、9.2 | 【暫定 S-1】実物で確認 |
| ブラウザ内の保存 | IndexedDB は数百MB以上を保存できる。Safari は7日間サイトを使わないと保存データを消すことがある(ホーム画面に追加した Web アプリは対象外。ただし Safari とは保存領域が別)。永続化を求める API がある | 9.1 | 【暫定 S-7】実機で確認 |
| 静的書き出し | Next.js の静的書き出しでは、サーバー側の機能(Route Handlers、Server Actions、proxy、画像最適化、設定ファイルでのヘッダ指定)は使えない | サーバー側の機能を使わない設計にする(P-2)。ヘッダは Netlify で付ける | 【決定】 |
| liqe | AND/OR に優先順位が無い、記号でエラーになりやすいなどの癖を、規則で吸収できることを試作で確認。ブラウザでも動く | 9.3 | 【決定】 |
| ブラウザ内の検索 | 試作の照合処理(JS の参照評価)は SQL の結果と一致した。数万件の部分一致の照合は、一般的な端末で数十ミリ秒程度の見込み | 9.3 | 【暫定 S-6】実機で計測 |
| ホスティング | 静的配信だけなら、Netlify の関数のタイムアウト・リージョン・レート制限の問題は生じない | 12.4 | 【暫定 S-4】 |
| 旧 検証1〜6 | Foursquare OAuth・API・revoke・Supabase CLI に関する検証 | API も Supabase も使わないため不要 | — |
