# 8. 内部インタフェース一覧(画面・ワーカー)

> [基本設計書 目次](README.md) ｜ 前: [7. インタフェース設計](07_インタフェース設計.md) ｜ 次: [9. 方式設計](09_方式設計.md)

---

サーバー側の API は無い。画面の URL と、画面とワーカーの間のメッセージだけで構成する。

## 8.1 画面の URL

| URL | 画面 | `#` 以降に持つ状態 |
|---|---|---|
| `/` | トップ | — |
| `/import` | 取り込み | — |
| `/search` | 検索・一覧、詳細(シート) | `q`(検索式)、`page`、`size`、`id`(詳細を開いているとき) |
| `/data` | データ管理 | — |
| `/about`、`/privacy` | 説明・ポリシー | — |

すべて静的に書き出したページで、表示の中身はブラウザの中で作る。`#` 以降の値は画面で検証し、不正な値は既定値にする。

`#` 以降の読み取りと更新の方式:

- `#` 以降は静的に書き出すときには存在しないため、ブラウザの中でだけ読む。最初の表示では骨組み(スケルトン)を出し、読み取った後に検索する(`useSyncExternalStore` で購読し、書き出した HTML との食い違いを起こさない)。
- 値の組み立てと読み取りは `URLSearchParams` で行う。Next.js の `useSearchParams` は `?` 以降を扱うもので、`#` 以降には使えないため使わない。
- 状態の更新は自前の関数で `history.pushState`(検索・ページ移動・詳細を開く)と `history.replaceState`(表示件数の変更など、履歴を増やさないもの)を呼び、`popstate` と `hashchange` で戻る/進むと手入力の変更を受け取る。

## 8.2 画面と取り込みワーカーのメッセージ

| 方向 | メッセージ | 内容 |
|---|---|---|
| 画面 → ワーカー | 形式の移行 | 起動時に保存形式が古い場合(9.1.3) |
| ワーカー → 画面 | 移行の結果 | 完了 / 保留(他のタブが古い版で開いている) / 失敗 |
| 画面 → ワーカー | 分析の開始 | 選ばれたファイル(ZIP、展開済みのフォルダ、または JSON) |
| ワーカー → 画面 | 分析の進捗 | 読み込んだファイル数・件数 |
| ワーカー → 画面 | 分析の結果 | 件数・期間・新規・更新・変更なし・不正・削除候補の件数、ファイルの完全性、削除の安全条件の判定、警告 |
| 画面 → ワーカー | 保存の開始 | 削除候補を反映するかどうか |
| ワーカー → 画面 | 保存の進捗 | 保存した件数 |
| ワーカー → 画面 | 完了 / エラー | 結果の件数、またはエラー種別 |
| 画面 → ワーカー | 中止 | 分析・保存の中止(保存の中止は「途中で終わった」状態になる) |

## 8.3 画面と検索ワーカーのメッセージ

| 方向 | メッセージ | 内容 |
|---|---|---|
| 画面 → ワーカー | 準備 | 検索用データ(search_index)の読み込み(起動時・取り込みの後) |
| 画面 → ワーカー | 破棄 | メモリ上の検索用データを捨て、データベースへの接続を閉じる(データの削除の前) |
| ワーカー → 画面 | 準備完了 | 件数 |
| 画面 → ワーカー | 検索 | 中間AST(空なら全件)、件数、ページ |
| ワーカー → 画面 | 検索結果 | 総件数、補正後のページ、表示ページ分のチェックイン(写真の情報を含む) |
| 画面 → ワーカー | 詳細 | チェックインID |
| ワーカー → 画面 | 詳細の結果 | チェックインと写真の情報(見つからなければその旨) |

## 8.4 タブ間の連絡

| 仕組み | 用途 |
|---|---|
| Web Locks(`navigator.locks`) | 取り込み・データの削除・保存形式の移行の排他(同じ名前の排他ロックを使う)。取り込みでは、分析の開始から保存の完了まで保持する(分析の後に別のタブが保存すると、算出した差分が古くなるため) |
| BroadcastChannel | 取り込みの完了を他のタブに知らせる。受け取ったタブは検索用データを読み直す |
| IndexedDB の `versionchange` | データの削除と保存形式の移行のとき、ブラウザが他のタブの接続に送る通知。受け取ったタブは、すべての接続(画面・ワーカー)を閉じてメモリ上のデータを捨て、自動では開き直さない(9.6) |

メッセージの項目定義は詳細設計書で定める。
