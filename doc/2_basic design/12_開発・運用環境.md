## 12.1 環境

| 環境 | 内容 | 用途 |
|---|---|---|
| ローカル | `next dev`(localhost:3000) | 開発 |
| プレビュー | Netlify のデプロイプレビュー(プルリクエストごと) | 確認 |
| 本番 | Netlify(静的配信) | 公開 |

サーバー側のデータベースや認証が無いため、環境ごとの設定・秘密情報の切り替えは不要になる。ただし保存領域はドメインごとに別なので、プレビューと本番ではデータが共有されない(それぞれで読み込む)。

## 12.2 ローカル開発(L-01、L-02、L-05)

| 要件 | 方式 |
|---|---|
| L-01 | `npm run dev`(`next dev`)だけで開発できる。Docker・Supabase は不要 |
| L-02 | IndexedDB の保存形式に版番号を付け、版の移行処理をコードで管理する(9.1.3)。移行処理には単体テストを付ける |
| L-05 | テスト用のデータは、**架空のデータから生成したもの**を主に使う。件数を指定して疑似的なエクスポート(ZIP・展開済みのフォルダ・形の揺れや欠損を含むもの)を作るスクリプトを用意し、取り込み・検索・性能のテストに使う。S-1 で取得した実物から作るものは、形式の確認に必要な最小限の件数に絞り、ID・店名・コメント・位置・写真の URL をすべて架空の値に置き換える。**実物の ZIP と JSON はリポジトリに入れない**(`.gitignore` に `*.zip` と実データ用のフォルダを入れる) |

## 12.3 環境変数

秘密の環境変数は無い。ビルド時の設定(アプリ名・上限値など)はコードの定数として持つ。Node のバージョンは `.nvmrc`(24)と `package.json` の engines でそろえ、Netlify のビルドでも同じ版を使う。

## 12.4 デプロイ

- Git リポジトリと連携し、Netlify のクラウドでビルドする。main ブランチを本番にする。
- ビルドは `next build`(静的書き出し、`output: 'export'`)で `out/` を作り、ビルド後に各 HTML のインラインスクリプトのハッシュを計算して、CSP を書いた `out/_headers` を生成する(10.2)。内容の変わらないヘッダは `netlify.toml` に書く。Netlify は `out/` を配信する。
- GitHub と Netlify のアカウントは2段階認証を必須にし、main ブランチを保護する。Netlify の Snippet injection は使わない。デプロイの通知を受け取る(10.1)。
- Netlify の Functions・Edge Functions は使わない。
- クレジット制のプランでは、本番デプロイ1回で15クレジット、帯域 1GB で20クレジットを消費する(無料プランは月300クレジット)。静的配信だけなら費用の大半はデプロイなので、本番デプロイの回数を絞る(月20回程度が無料プランの目安)。確認はデプロイプレビューで行う。

## 12.5 テスト方針

| レベル | 対象 | ツール |
|---|---|---|
| 単体 | 検索式の解析・中間AST 変換、照合(AND/OR/括弧・正規化)、エクスポートの形式判定とレコードの検証・raw の組み立て直し(形の揺れ・欠損・未知の項目を含む)、写真の対応付けと URL の検証、差分と削除の安全条件、ページ計算、日時表示、`#` 以降の値の検証 | Vitest 5 |
| 保存 | IndexedDB への保存・差分の反映・削除・保存形式の移行・取り込みの途中終了からの回復 | Vitest + IndexedDB の模擬実装(fake-indexeddb など) |
| E2E | 取り込み(架空データの fixture)→ 検索 → 詳細 → ページ移動 → データの削除、複数タブ(取り込み中の削除、削除後の他のタブ、bfcache からの復帰)、ライト/ダークの表示、CSP の違反が起きないこと | Playwright |
| 性能 | 疑似エクスポートで5万件・20万件の取り込み時間と検索時間 | Playwright(ローカル)+ 実機 |
| 実地 | 実際のエクスポートの読み込み、iPhone・Android 実機での保存の永続化 | 手動(報告書 16.3 の手順) |
