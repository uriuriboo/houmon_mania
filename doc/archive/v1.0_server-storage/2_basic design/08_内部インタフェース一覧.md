# 8. 内部インタフェース一覧(画面・API)

> [基本設計書 目次](README.md) ｜ 前: [7. インタフェース設計](07_インタフェース設計.md) ｜ 次: [9. 方式設計](09_方式設計.md)

---

| 種別 | メソッド・パス | 概要 | ログイン | CSRF 対策 | レート制限 |
|---|---|---|---|---|---|
| 画面 | GET `/`、`/login/email`、`/about`、`/privacy`、`/terms` | トップ、メールログイン、説明・ポリシー | 不要 | — | — |
| 画面 | GET `/auth/confirm` | メールのリンクの着地点(確認画面を表示するだけ) | 不要 | — | — |
| Route Handler | GET `/auth/callback` | Google ログインの完了(コード交換) | 不要 | PKCE(検証値の Cookie) | IP 単位 |
| 画面 | GET `/welcome` | 利用同意 | 要 | — | — |
| 画面 | GET `/import`、`/search`、`/checkins/[id]` | 取り込み、検索・一覧、詳細(副作用なし) | 要・同意 | — | 検索(ユーザー単位) |
| 画面 | GET `/account` | マイページ | 要 | — | — |
| Route Handler | POST `/api/import` | 取り込みの開始 | 要・同意 | Origin ヘッダ検証 | ユーザー単位 |
| Route Handler | POST `/api/import/[id]/chunk` | チェックインの分割送信(連番付き) | 要・同意 | 同上 | ユーザー単位 |
| Route Handler | POST `/api/import/[id]/finish` | 取り込みの完了と差分の集計 | 要・同意 | 同上 | ユーザー単位 |
| Route Handler | POST `/api/import/[id]/confirm-deletions` | 削除候補を削除して完了 | 要・同意 | 同上 | ユーザー単位 |
| Route Handler | POST `/api/import/[id]/keep` | 削除せずに完了 | 要・同意 | 同上 | ユーザー単位 |
| Server Action | Google ログイン開始 | AUTH-01 | 不要 | Next.js 標準の Origin 検証 | IP 単位 |
| Server Action | メール送信 / リンクの確認 / コードの確認 | AUTH-02 | 不要 | 同上 + CAPTCHA + ログイン意図の Cookie | IP 単位・メールアドレス単位 |
| Server Action | 同意する / 同意しない | CONS-01 | 要 | 同上 | — |
| Server Action | ログアウト / すべての端末からログアウト | AUTH-03 / AUTH-04 | 要 | 同上 | — |
| Server Action | データの削除 / アカウントの削除 | ACCT-02 / ACCT-03 | 要 | 同上 | — |

- 「要・同意」は、ログインに加えて現在の版に同意済みであることを処理の中で確認し、未同意なら 403(画面は `/welcome` へリダイレクト)にすることを示す。
- 取り込みは Route Handler(JSON)にする。Server Actions はクライアントから1件ずつ順番に実行され、Cookie を設定すると画面の再描画が走るため、繰り返し呼ぶ処理に向かない。
- 入出力の項目定義は詳細設計書で定める。
