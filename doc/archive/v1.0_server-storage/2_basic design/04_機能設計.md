## 4.2 処理の流れ

### 4.2.1 Google ログイン — AUTH-01

```mermaid
sequenceDiagram
  autonumber
  actor U as 利用者
  participant B as ブラウザ
  participant N as Next.js(サーバー)
  participant A as Supabase Auth
  participant G as Google
  participant D as Postgres
  U->>B: 「Google でログイン」
  B->>N: POST(Server Action)ログイン開始
  N->>A: signInWithOAuth(provider google、PKCE)
  N-->>B: 303 Supabase Auth の認可 URL へ(PKCE の検証値を httpOnly Cookie に保存)
  B->>A: 認可リクエスト
  A-->>B: 302 Google のログイン画面へ
  B->>G: ログイン・同意
  G-->>B: 302 Supabase Auth へ
  B->>A: 認可コードを渡す(Supabase Auth のコールバック)
  A-->>B: 302 /auth/callback?code=...
  B->>N: GET /auth/callback
  N->>A: コード交換(転送元IP付き Auth クライアント、Cookie の検証値を使用)
  N->>N: セッションをユーザークライアントに設定し、httpOnly Cookie に保存
  N->>D: アカウント情報を取得(初回なら作成)
  alt アカウント削除の処理中
    N->>A: サインアウト
    N-->>B: 303 /(「削除処理中です」)
  else 同意が未取得、または旧版
    N-->>B: 303 /welcome
  else データ0件
    N-->>B: 303 /import
  else それ以外
    N-->>B: 303 /search
  end
```

### 4.2.2 メールでログイン — AUTH-02

```mermaid
sequenceDiagram
  autonumber
  actor U as 利用者
  participant B as ブラウザ
  participant N as Next.js(サーバー)
  participant T as Turnstile
  participant A as Supabase Auth
  participant M as メール
  U->>B: メールアドレスを入力し、CAPTCHA を通過
  B->>N: POST(Server Action)メール送信の依頼
  N->>T: CAPTCHA トークンを検証(ホスト名・アクション名・使い捨て)
  N->>N: レート制限(IP・メールアドレス)を確認
  N->>A: signInWithOtp(転送元IP付き Auth クライアント)
  A->>M: リンクとコードを記載したメールを送信
  N-->>B: 「メールを送りました」(コード入力欄)。ログイン意図の Cookie を発行
  alt リンクから
    U->>B: メールのリンクを開く
    B->>N: GET /auth/confirm?token_hash=...(この時点ではログインしない)
    N-->>B: 確認画面(URL からトークンを消し、フォームに保持)
    U->>B: 「ログインする」(ログイン意図の Cookie が無い場合は、メールアドレスの入力と CAPTCHA も求める)
    B->>N: POST(Server Action)確認
    N->>A: verifyOtp(token_hash、転送元IP付き Auth クライアント)
  else コードから
    U->>B: コードを入力(CAPTCHA を含む)
    B->>N: POST(Server Action)コード確認
    N->>N: メールアドレス単位の失敗回数を確認
    N->>A: verifyOtp(email・コード、転送元IP付き Auth クライアント)
  end
  N->>N: ログインしたユーザーのメールアドレスが、意図した(または入力された)アドレスと一致することを確認。不一致ならサインアウト
  N->>N: セッションを httpOnly Cookie に保存
  N-->>B: 303 4.2.1 と同じ分岐
```

- リンクを開いただけではログインしない。メールのセキュリティ製品がリンクを先読みしてワンタイムトークンを消費する問題を避けるため。
- **他人から転送されたリンクでのログインを防ぐ**: 送信時に、メールアドレスのハッシュに紐づく短命の httpOnly Cookie(ログイン意図)を発行する。確認時にこの Cookie が無い場合(別のブラウザで開いた場合など)は、利用者にメールアドレスを入力してもらい、ログインしたユーザーのアドレスと一致しなければ即座にサインアウトする。攻撃者が自分宛のリンクを転送して、被害者を攻撃者のアカウントにログインさせ、被害者のデータを取り込ませる攻撃への対策。あわせて、利用同意・取り込みの画面に「xxx@… のアカウントに取り込みます」と表示する。
- コードの桁数は Supabase の設定値に従い、画面で桁数を固定しない。コードの有効期限は10分以下にする。
- 送信の結果は、アドレスが登録済みかどうかにかかわらず同じ表示にする。

### 4.2.3 エクスポートの取り込み — IMPT-01〜05

```mermaid
sequenceDiagram
  autonumber
  actor U as 利用者
  participant B as ブラウザ(Web Worker)
  participant N as Next.js(Route Handler)
  participant D as Postgres
  U->>B: エクスポートの ZIP を選択
  B->>B: ZIP の目次を読み、checkins*.json と photos*.json だけを展開
  B->>B: 形式とファイルの欠けを検証、ID の重複を除去、写真を対応付け
  B-->>U: 件数・期間・確認結果を表示
  U->>B: 「取り込む」
  B->>N: POST /api/import(総件数、ファイルの完全性)
  N->>D: 取り込みを登録(利用者単位で排他。古い取り込みは中止。開始時点の保存件数・期間を控える)
  loop 全件を送るまで(1回500件以下・1MB 以下、連番付き)
    B->>N: POST /api/import/{id}/chunk
    N->>N: 認証・同意を確認し、各レコードを検証して raw を組み立て直す
    N->>D: RPC で保存(利用者単位で排他。連番の重複は無視。件数上限・レート制限を確認)
    N-->>B: 受領結果
    B-->>U: 進捗を表示
  end
  B->>N: POST /api/import/{id}/finish
  N->>D: 受領件数と期間を照合し、新規・更新・変更なし・削除候補を集計
  alt 削除候補なし、または安全条件を満たさない
    N->>D: 完了にする(削除しない)
    N-->>B: 結果
  else 削除候補があり、安全条件を満たす
    N-->>B: 結果と削除の確認
    alt 利用者が「削除する」
      B->>N: POST /api/import/{id}/confirm-deletions
      N->>D: 最新の取り込みで確認待ちであること、候補数が変わっていないことを確かめて削除し、完了にする
    else 利用者が「残しておく」
      B->>N: POST /api/import/{id}/keep
      N->>D: 削除せずに完了にする
    end
  end
```

### 4.2.4 検索 — SRCH-01 / SRCH-02

```mermaid
sequenceDiagram
  autonumber
  participant B as ブラウザ
  participant N as Next.js(サーバー)
  participant D as Postgres
  B->>N: GET /search?q=...&page=2&size=50
  N->>N: 認証・同意を確認。長さ確認、空白・括弧・引用符の正規化、liqe でパース、規則の検証、中間AST に変換
  alt 検索式のエラー
    N-->>B: 検索画面とエラーメッセージ(原因と書き方の例)
  else 正常
    N->>D: RPC search_checkins(中間AST, 件数, 開始位置)をユーザーの JWT で実行(POST)
    D->>D: 引数の検証、レート制限判定、中間AST の再検証、語の正規化とエスケープ、WHERE 句の生成(語は USING でバインド)、RLS 適用
    D-->>N: 総件数と該当ページのチェックイン
    N-->>B: タイムラインと「解釈」を描画
  end
```

### 4.2.5 データ・アカウントの削除 — ACCT-02 / ACCT-03 / BATCH-01

```mermaid
sequenceDiagram
  autonumber
  actor U as 利用者
  participant B as ブラウザ
  participant N as Next.js(サーバー)
  participant A as Supabase Auth
  participant D as Postgres
  U->>B: 「データを削除」または「アカウントを削除」を選び、確認ダイアログで確定
  B->>N: Server Action(削除)
  N->>A: getUser() でセッションが有効か確認
  N->>D: DB 関数で削除要求を記録(実行中・確認待ちの取り込みは中止。以後 RLS でデータは見えなくなり、取り込みは拒否される)
  opt アカウントの削除
    N->>A: 全セッションを終了(scope: global)
  end
  N-->>B: 303 完了画面(データの削除はマイページ、アカウントの削除はトップ)
  Note over D: BATCH-01(10分ごと)が物理削除し、<br/>アカウントの削除では最後に Supabase のユーザーも削除する
```
