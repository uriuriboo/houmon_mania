# 16. リスクと対応

> [基本設計書 目次](README.md) ｜ 前: [15. 要件トレーサビリティ](15_トレーサビリティ.md) ｜ 次: [17. レビューで判断いただきたい事項](17_判断事項.md)

---

| No | リスク | 影響 | 対応 |
|---|---|---|---|
| R-1 | エクスポートの実際の形式が想定と違う(2026年版は未確認) | 取り込みができない・項目が欠ける | S-1 で実物を確認してから詳細設計の取り込み仕様を確定する。形式の判定と変換を1か所にまとめる |
| R-2 | エクスポートの形式が予告なく変わる | 新しいエクスポートを取り込めない | 形式エラーと未知の項目名を検知して案内・記録し、改修する。raw を保存する |
| R-3 | Foursquare がエクスポート機能を変更・停止する | 新しいデータを取り込めない | 取り込み済みのデータの検索は続けられる。公式は継続を表明している |
| R-4 | 検索できる項目が店名・コメントに限られ、期待と違う | 利用者の満足度が下がる | トップ・ヘルプ・該当なし画面で「できること・できないこと」を明示する。座標が含まれていれば、公開データで市区町村を補う拡張を検討する(17章 D-7) |
| R-5 | 自動更新が無く、データが古くなる | 最近のチェックインが検索できない | 鮮度の表示と再申請の案内(9.2.6) |
| R-6 | 規約の解釈(店名などは個人的・非商用の利用許諾) | 商用化した場合に問題になりうる | 非商用を前提とし、商用化する前に法務確認を行う |
| R-7 | 大きなエクスポートでブラウザの処理が重い(特にスマホ) | 取り込みに失敗する | 必要なファイルだけを展開する、Web Worker で処理する、S-5 で計測する。展開済みの JSON を直接選べるようにする |
| R-8 | 取り込みの誤操作・競合で、必要なデータを削除してしまう | データの消失 | 削除候補の安全条件、利用者の確認、確定時の再確認(9.2.4)。エクスポートを再アップロードすれば復元できる |
| R-9 | Supabase Auth の IP 単位のレート制限がサーバーの IP に集中する | ログインやセッション更新が失敗する | 転送元IP付き Auth クライアントと上限の引き上げ(S-2・S-4 で確認) |
| R-10 | ログインの悪用(メール爆撃、コードの総当たり、リンクの転送) | 送信上限の枯渇、アカウントの乗っ取り、意図しないアカウントへの取り込み | CAPTCHA、レート制限、ログイン意図の確認(4.2.2、9.6) |
| R-11 | 無料の Google アカウントで大量のアカウントを作り、容量を消費される | DB 容量・費用の増加 | 1利用者の件数・raw の大きさの上限、取り込みの頻度制限、DB 容量の監視 |
| R-12 | Netlify 上で proxy.ts が正しく動かない | セッション更新・CSP が機能しない | S-4 で確認し、middleware.ts に切り替える |
| R-13 | 開発機で Docker を使えない | ローカル開発の要件(L-01)を満たせない | 仮想化の有効化と Docker Desktop の導入。それまでは開発用クラウドプロジェクトで代替 |
| R-14 | 使う Netlify アカウントがレガシープランかクレジット制かで、上限・料金・関数のタイムアウトが変わる | プラン選定と性能の前提が崩れる | S-4 の前にアカウント種別を確認する。どちらでも動くよう1リクエスト10秒以内を守る(P-4) |
