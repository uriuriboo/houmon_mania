| 項目 | 目標・方式 | 要件 |
|---|---|---|
| 検索の応答 | 利用者1人あたり5万件のとき、サーバー処理時間 p95 500ms 以内(S-6 で計測) | N-05 |
| 画面表示 | 主要画面の初期表示 2秒以内(モバイル回線相当)【提案】。関数と DB を同じリージョンに置く(日米に分かれると DB への問い合わせのたびに約136ms 加算されるため) | — |
| 取り込み | 1万件を数十秒〜1分程度で取り込む(1回500件、送信と保存で1秒前後を想定。S-5 で計測)。どの関数も1リクエスト10秒以内(P-4) | — |
| 削除 | 削除の要求から通常1時間以内に物理削除する(9.5) | F-40 |
| 可用性 | Netlify / Supabase の SLA に準じる。単一リージョン。Supabase の無料プランは1週間アクセスが無いと一時停止するため、公開時は有料プランにする | — |
| 外部依存 | Foursquare のエクスポートの形式は文書化されておらず変わりうる。形式の判定と変換を1か所にまとめ、raw を保存し、未知の項目名をログで把握する | N-06 |
| データ保全 | raw を保持する。バックアップは Supabase の機能(プランによる)。バックアップに残る期間をプライバシーポリシーに書く | N-06 |
| 容量 | 1行あたり約1KB(raw・索引を含む見込み、raw は最大2KB)。20万件の利用者で約200〜400MB。公開時は Supabase Pro(DB 8GB 込み)を前提とし、DB の容量を監視する | — |
| 個人情報 | 位置情報を扱うため、同意(CONS-01)と、9.5 に挙げる事項を記載したプライバシーポリシーを公開前に整える | N-11 |
| 拡張性 | 利用者が増えた場合は Supabase / Netlify のプラン変更で対応する | — |
| 保守性 | TypeScript と DB からの型生成による型安全、マイグレーション管理、単体テストと DB テスト。依存関係の自動更新 | — |
| アクセシビリティ | WCAG 2.2 AA 相当 | — |
