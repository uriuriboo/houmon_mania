# 3. 技術調査の結果と方式決定

> [基本設計書 目次](README.md) ｜ 前: [2. システム概要](02_システム概要.md) ｜ 次: [4. 機能設計](04_機能設計.md)

---

詳細と根拠は技術調査報告書を参照。

| 項目 | 結論 | 方式 | 状態 |
|---|---|---|---|
| 規約 | API で得たデータはサーバー保存禁止。エクスポートは利用者本人のデータで、規定が及ばない可能性が高い | エクスポート方式に変更(0.1) | 商用化時は法務確認 |
| エクスポートの形式 | `checkins*.json`(1000件ずつ)と `photos*.json` などを含む ZIP。チェックインの venue は ID・名前・URL のみ。座標の有無は情報が矛盾 | 7.1、9.2 | 【暫定 S-1】実物で確認 |
| 認証 | Supabase Auth の Google ログインとメールのワンタイムリンク・コード。CAPTCHA は secret key で呼ぶと Supabase 側で検証されないため、アプリ側で検証する | 7.2、9.1 | 【暫定 S-2】 |
| Supabase CLI(旧 検証6) | `supabase start` には Docker か Podman が必須 | Docker 導入を前提にし、代替として開発用クラウドプロジェクトを用意(12.2) | 【暫定 S-3】 |
| liqe(旧 検証7) | AND/OR に優先順位が無い、記号でエラーになりやすいなどの癖を、規則で吸収できることを試作で確認 | 9.3 | 規則の一部は【提案】(17章 D-4・D-5) |
| ホスティング | Netlify の同期関数は公式60秒(レガシープランは10秒の報告)、リクエスト6MB、関数の既定リージョンは米国 Ohio | 1章、P-4 | 【暫定 S-4】 |
| 旧 検証1〜5 | Foursquare OAuth・API・revoke に関する検証 | API を使わないため不要 | — |
