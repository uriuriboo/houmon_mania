本書は、要件定義書と要件変更一覧を受けて、システムを「どう実現するか」の方式を定める。

| 区分 | 内容 |
|---|---|
| 本書の範囲 | システム構成、機能構成、画面構成・画面遷移・UI方針、論理データ設計、インタフェース概要、主要処理方式(認証・取り込み・検索・データ削除)、セキュリティ、非機能、開発・運用環境、技術スタックの確定 |
| 範囲外(詳細設計書で扱う) | テーブル物理設計(DDL・型・インデックス・制約の最終値)、API の入出力項目定義、画面項目定義・コンポーネント設計、メッセージ/エラーコード一覧、例外分岐を含む詳細シーケンス、テスト設計 |

## 0.1 方式変更の経緯

技術調査で、Foursquare の API 利用ガイドラインが一般の開発者にデータのサーバー保存を禁じていることが分かった。2026-10-16 のユーザー判断で、**利用者が Foursquare 公式のデータエクスポートを自分で取得してアップロードする方式**に変更した。本アプリは Foursquare API を一切使わない。ログインは Google とメールのワンタイムリンク(またはコード)で行う。

この方式では、エクスポートに住所・カテゴリが含まれないため、**検索対象は店名とコメント(shout)が中心になる**(F-22 の変更)。新しいチェックインを反映するには、利用者がエクスポートを再申請してアップロードし直す必要がある。

## 0.3 用語

| 用語 | 意味 |
|---|---|
| エクスポート | Foursquare 公式のデータダウンロード(Swarm / Foursquare の設定 → Privacy Settings → "Initiate Data Download Request")で届く ZIP ファイル |
| チェックインレコード | エクスポートの `checkins*.json` に入っている、チェックイン1件分の JSON |
| 取り込み | エクスポートを読み込み、チェックインを本アプリの DB に保存する一連の処理。1回の取り込みを `imports` の1行で管理する |
| venue | チェックイン先のスポット(店・施設)。エクスポートには ID・名前・Foursquare 上の URL だけが入っている |
| shout | チェックイン時に本人が書いたコメント。本書では「コメント(shout)」と書く |
| raw | チェックインレコードから、保存してよい項目だけを取り出して組み立て直した JSON(9.2.3) |
| 中間AST | 検索式を解析した結果を、AND / OR / 語 だけで表した木構造(JSON) |
| ユーザークライアント | ログイン中の利用者のセッション(JWT)で Supabase に接続するサーバー側クライアント(publishable key)。RLS が適用される |
| 転送元IP付き Auth クライアント | secret key で接続し、利用者の IP を `Sb-Forwarded-For` ヘッダで渡して、Supabase Auth の API(メール送信・コード確認・コード交換・リフレッシュ)だけを呼ぶサーバー専用クライアント。DB には接続しない |
| 管理クライアント | secret key で接続するサーバー専用クライアント。RLS をバイパスする。用途は初回同意を拒否したアカウントの即時削除など最小限にする |
